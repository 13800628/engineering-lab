# Engineering Lab

技術的な学習・実験・検証を行うための個人リポジトリ。

## 目的

技術への理解を深め、実験や検証を通じて得た知見を蓄積する。

## 分野

| ディレクトリ   | 内容                             |
| -------------- | -------------------------------- |
| backend        | バックエンド開発                 |
| frontend       | フロントエンド開発               |
| infrastructure | インフラ・開発環境               |
| architecture   | ソフトウェア設計・アーキテクチャ |
| tools          | 開発ツール・技術検証             |
| templates      | 実験用テンプレート               |

## 使用する技術

| 言語       | ランタイム・ビルドツール |
| ---------- | ------------------------ |
| Java       | Gradle / Maven           |
| TypeScript | Node.js                  |
| Go         | Go modules               |
| Python     | uv                       |

バージョンは実験開始時点の最新安定版を使い、各実験の `CONTEXT.md` に明記する。

## 実験の作り方

1. 分野のディレクトリ内に、実験名のフォルダを作る
2. `templates/experiment` の中身をコピーする
3. `CONTEXT.md` の目的・技術・選定理由を埋める
4. コードを書き、動いたら結果と気づきを追記する

## ルール

- 各実験は独立させる。他の実験のコードや依存を参照しない
- ビルド設定(`package.json`、`go.mod`、`build.gradle`、`pyproject.toml` など)は実験フォルダ直下に置き、リポジトリのルートには置かない
- 依存・ビルド成果物は実験フォルダ内に閉じる
- Gradleのマルチプロジェクトやnpm workspacesは使わない
- サーバー系の実験は、ポート番号を `CONTEXT.md` に明記して衝突を避ける
- 秘密情報は `.env` に置き、コミットしない。必要な項目は `.env.example` に書く
